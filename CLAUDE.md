# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

OpenAI-compatible HTTP proxy that wraps the `claude` Code CLI as a subprocess,
exposing `/v1/chat/completions` and `/v1/models`. No Anthropic API is called
directly — auth flows through the user's existing Claude Code login.

The proxy itself is authenticated: clients must pass an `Authorization: Bearer
<API_KEY>` header that matches the `API_KEY` env var (typically loaded from
`.env`, generated by `generate_api_key.py`).

## Running

```bash
python3 generate_api_key.py     # first time: create API_KEY in .env
./start-proxy.sh                # venv + deps + uvicorn on 127.0.0.1:8001
PORT=9000 ./start-proxy.sh      # override port
SKIP_INSTALL=1 ./start-proxy.sh # faster restart, skip pip install
```

`smoke_test.py` hits `/health`, `/v1/models`, and one streaming + one non-streaming
completion against a running proxy. Run it after changes that touch request/response
wiring.

```bash
./smoke_test.py                       # full test against http://localhost:8001
SKIP_COMPLETION=1 ./smoke_test.py     # check HTTP surface only (no claude binary needed)
SKIP_AUTH=1 ./smoke_test.py           # confirm 401 behavior
```

There is no unit test suite and no linter. For tool-calling or other deeper changes,
exercise the endpoints manually.

## Architecture

`claude_proxy.py` is a single-file FastAPI app organized in these sections (in order):

1. **`.env` loader** — stdlib-only parser that runs at import time so env vars
   are available before config is read.
2. **Config** — env vars (`API_KEY`, `CLAUDE_BIN`, `DEFAULT_MODEL`, `LOG_LEVEL`,
   `LOG_PROMPTS`, `CLI_TIMEOUT_SECONDS`, `MAX_REQUEST_BYTES`,
   `MAX_SYSTEM_PROMPT_BYTES`, `SESSION_CACHE_SIZE`, `SESSION_CACHE_TTL_SECONDS`,
   `MAX_CONCURRENT_CLI`, `CLAUDE_MODELS`) and the default model allowlist.
3. **`OpenAIError`** — structured error with OpenAI-style JSON body
   (`{error: {message, type, code, param}}`). Surfaced via a FastAPI exception
   handler. All request-path errors must use this, never raw `HTTPException`.
4. **Pydantic request models** — `ChatRequest`, `Tool`, `ToolFunction`.
5. **Session cache** — `_SessionCache` is an OrderedDict LRU with TTL, keyed on
   SHA-256(`user + ":" + system_prompt`). Captured `session_id` from CLI
   result/system events is stored on success, invalidated on non-zero exit.
6. **Prompt construction** — `build_prompt` flattens OpenAI `messages` into a
   `User:` / `Assistant:` / `Tool Result:` transcript. Assistant messages with
   `tool_calls` are re-serialized as `` ```json ``` `` fenced blocks so Claude
   sees its prior tool invocations. `tool` messages are labeled with the function
   name (resolved via `tool_call_id` → name map). `system` messages are
   concatenated and passed via `--system-prompt`. Tool specs are injected into
   the system prompt using `_TOOL_BLOCK_TEMPLATE`. Non-text content blocks raise
   `OpenAIError` (HTTP 400).
7. **CLI invocation** — `_run_claude` spawns `claude --print` with either
   `--output-format json` (non-streaming) or `stream-json --verbose
   --include-partial-messages` (streaming). When `has_tools=True` it passes
   `--allowedTools ""` so Claude cannot execute its own built-in tools.
   When a `cache_key` hits, it adds `--resume <session_id>`. Enforces
   `CLI_TIMEOUT_SECONDS` and terminates the subprocess on client disconnect or
   timeout. Concurrency is capped by `MAX_CONCURRENT_CLI` via an asyncio
   semaphore.
8. **Output parsing** — `_extract_tool_calls` pulls `` ```json `` fenced blocks out
   of Claude's text and converts them to OpenAI `tool_calls`. Accepts both
   `arguments` (spec) and `parameters` (common model mistake).
   `_collect_result_text` prefers the `result` field of the stream's `result`
   event, falling back to concatenating assistant text blocks.
9. **Response helpers / streaming generators / FastAPI app** — `_stream_text_only`
   emits true incremental deltas for no-tool requests. `_stream_with_tools` buffers
   the full response before emitting, since tool-call JSON fences must be parsed
   atomically (streaming them token-by-token would leak raw JSON to clients).
10. **Auth + middleware** — `_require_api_key` validates Bearer tokens with
    `secrets.compare_digest`. A middleware rejects bodies larger than
    `MAX_REQUEST_BYTES` with HTTP 413.

## Important behaviors

- `usage` token counts are always `0` — the CLI doesn't expose per-call counts.
- `temperature` and `max_tokens` are accepted but ignored.
- `tool_choice="none"` disables tool injection entirely. All other values are
  treated as `"auto"`.
- Unknown model names return HTTP 400 (`code: "model_not_found"`).
- `CLAUDE_HOME` is set to `~/.claude-proxy` (override with `CLAUDE_PROXY_HOME`)
  so the subprocess doesn't pay startup cost for the user's MCP servers.
- The CLI is invoked with `--dangerously-skip-permissions` — intentional since
  built-in tools are disabled for tool-calling requests.
- Default bind is `127.0.0.1`. Exposing on `0.0.0.0` is safe as long as
  `API_KEY` isn't leaked.
- Log prompt bodies and assistant output only under `LOG_PROMPTS=true` since they
  may contain user secrets.
