# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

OpenAI-compatible HTTP proxy that wraps the `claude` Code CLI as a subprocess,
exposing `/v1/chat/completions` and `/v1/models`. No Anthropic API is called
directly — auth flows through the user's existing Claude Code login.

The proxy itself is authenticated: clients must pass an `Authorization: Bearer
<API_KEY>` header that matches the `API_KEY` env var (typically loaded from
`.env`, generated by `generate_api_key.py`).

## Layout

- `claude_proxy.py` — the entire app. FastAPI with three endpoints
  (`/v1/chat/completions`, `/v1/models`, `/health`).
- `generate_api_key.py` — stdlib-only script that creates/rotates the API key
  in `.env` (chmod 600).
- `.env.example` — template showing all env vars and their defaults.
- `requirements.txt` — `fastapi`, `uvicorn`.
- `start.sh` — creates `.venv`, installs deps, runs `uvicorn claude_proxy:app`.
  Honors `HOST`, `PORT`, `SKIP_INSTALL`, and forwards extra args to uvicorn.
  Refuses to start if neither `.env` nor `API_KEY` env var is present.
- `smoke_test.py` — stdlib-only smoke test. Reads `API_KEY` from env/.env.

## Architecture notes

`claude_proxy.py` is one file organized in these sections (in order):

1. **`.env` loader** — stdlib-only parser that runs at import time so env vars
   are available before config is read.
2. **Config** — env vars (`API_KEY`, `CLAUDE_BIN`, `DEFAULT_MODEL`,
   `LOG_LEVEL`, `LOG_PROMPTS`, `CLI_TIMEOUT_SECONDS`, `MAX_REQUEST_BYTES`,
   `MAX_SYSTEM_PROMPT_BYTES`, `SESSION_CACHE_SIZE`, `SESSION_CACHE_TTL_SECONDS`,
   `CLAUDE_MODELS`) and the default model allowlist.
3. **`OpenAIError`** — structured error with OpenAI-style JSON body
   (`{error: {message, type, code, param}}`). Surfaced via a FastAPI exception
   handler.
4. **Pydantic request models** — `ChatRequest`, `Tool`, `ToolFunction`.
5. **Session cache** — `_SessionCache` is a simple OrderedDict LRU with TTL.
   Keyed on SHA-256 of the system prompt. Captured `session_id` from CLI
   result/system events is stored on success, invalidated on non-zero exit.
6. **Prompt construction** — `build_prompt` flattens OpenAI `messages` into a
   `User:` / `Assistant:` / `Tool Result:` transcript. Assistant messages with
   `tool_calls` are re-serialized as ` ```json ``` ` fenced blocks so Claude
   sees its prior tool invocations. `tool` messages are labeled with the
   function name (resolved via `tool_call_id` -> name map). `system` messages
   are concatenated and returned separately to be passed via `--system-prompt`.
   Tool specs are injected into the system prompt using `_TOOL_BLOCK_TEMPLATE`.
   Non-text content blocks (images, audio) raise `OpenAIError` (HTTP 400).
7. **CLI invocation** — `_run_claude` spawns `claude --print` with either
   `--output-format json` (non-streaming) or `stream-json --verbose
   --include-partial-messages` (streaming). When `has_tools=True` it passes
   `--allowedTools ""` so Claude cannot execute its own built-in tools.
   When a `cache_key` hits, it adds `--resume <session_id>`. Enforces
   `CLI_TIMEOUT_SECONDS` per-line and terminates the subprocess on client
   disconnect or timeout.
8. **Output parsing** — `_extract_tool_calls` pulls `json` fenced blocks out of
   Claude's text and converts them to OpenAI `tool_calls`. Accepts both
   `arguments` (spec) and `parameters` (common model mistake).
   `_collect_result_text` prefers the `result` field of the stream's `result`
   event, falling back to concatenating assistant text blocks.
9. **Response helpers / streaming generators / FastAPI app** — SSE formatting,
   `_stream_text_only` for no-tool streaming (true incremental deltas),
   `_stream_with_tools` (buffers full response, then emits text + tool_calls,
   since tool-call JSON fences must be parsed atomically).
10. **Auth + middleware** — `_require_api_key` validates Bearer tokens with
    `secrets.compare_digest`. A middleware rejects bodies larger than
    `MAX_REQUEST_BYTES` with HTTP 413.

## Important behaviors

- `usage` token counts are always `0` — the CLI doesn't expose per-call counts.
- `temperature` and `max_tokens` are accepted on the request but ignored.
- `tool_choice="none"` disables tool injection. Other values (specific function
  or `"auto"`) are treated as `"auto"`.
- Unknown model names return HTTP 400 (`code: "model_not_found"`).
- Non-text content blocks return HTTP 400. Only `{type: "text"}` is supported.
- `CLAUDE_HOME` is set to `~/.claude-proxy` (override with `CLAUDE_PROXY_HOME`)
  so the subprocess doesn't pay startup cost for the user's MCP servers.
- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` and `CLAUDE_BASH_NO_LOGIN=1` are
  set for speed.
- The CLI is invoked with `--dangerously-skip-permissions` — intentional since
  the proxy runs under the user's own account and built-in tools are disabled
  for tool-calling requests.
- Default bind is `127.0.0.1`. Auth is always required on `/v1/*`, so exposing
  on `0.0.0.0` is safe as long as the `API_KEY` isn't leaked.

## Running

```bash
python3 generate_api_key.py   # first time: create API_KEY in .env
./start.sh                    # venv + deps + uvicorn on 127.0.0.1:8001
./start.sh --reload           # forwarded to uvicorn for dev
PORT=9000 ./start.sh          # override port
SKIP_INSTALL=1 ./start.sh     # faster restart, skip pip install
```

`smoke_test.py` is a stdlib-only script that hits `/health`, `/v1/models`, and
one streaming + one non-streaming completion against a running proxy. Run it
after changes that touch request/response wiring. Use
`SKIP_COMPLETION=1 ./smoke_test.py` to check just the HTTP surface when no
`claude` binary is available. Use `SKIP_AUTH=1 ./smoke_test.py` to confirm
401 behavior. There is no unit test suite and no linter; for tool-calling or
other deeper changes, exercise the endpoints manually.

## Conventions

- Keep the app in one file unless something grows large enough to justify a
  split.
- Preserve the OpenAI wire format exactly — clients expect it. That includes
  the `error` body shape and the `401 invalid_api_key` code.
- Log at `INFO` for request/response boundaries; keep prompt bodies and
  assistant output behind `LOG_PROMPTS=true` since they may contain user
  secrets.
- Errors raised from anywhere in the request path should be `OpenAIError`
  (never raw `HTTPException`) so the response body is always OpenAI-shaped.
